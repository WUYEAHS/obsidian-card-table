# Card Table 路線圖與統一原則

> 2026-09-17 整理。根據 1.4.0 → 1.6.1 的更新紀錄、使用者寫的定位介紹,以及 Obsidian 任務類外掛的競品研究。
> ⚠ **狀態:建議,尚未採用**(2026-09-17 使用者明講)。路線圖的版本規劃只是提案,要做哪一項之前先跟使用者確認。
> 第 4 節的統一原則另外整理成專案技能 `card-table-principles`,平常照那份判斷。

## 1. 一句話定位

**以任務為導向的卡片日誌看板**:一份筆記就是一張看板,時間是主軸,卡片可以對話,永遠是純文字。
兩種檢視模式:表格模式(桌機、寬分頁)和卡片模式(手機、觸控);卡片用 Tasks / Dataview 的 `[欄位:: 值]` 寫法,其他外掛的查詢也讀得到。
長內容不在看板裡寫,用連結放到外面的筆記(2026-09-18 使用者決定,取代原本的沉浸模式)。

## 2. 競品地圖

| 產品 | 資料放哪裡 | 主要視圖 | 跟我們的關係 |
| --- | --- | --- | --- |
| **Kanban**(mgmeyers) | 一份筆記一個看板,`## 欄` + `- [ ]` | 看板 / 清單 / 表格 | **格式最接近,也是最大的遷移來源。** 下載約 267 萬,但最後一次發版是兩年前、550+ 個未解 issue,正在找新的維護者 |
| **Tasks** | 散在各筆記的 `- [ ]` + emoji 日期 | 查詢區塊(文字) | 查詢能力強,沒有視覺化看板;emoji 格式跟我們 1.6.1 以前很像 |
| **Task Genius** | 散在各筆記 | 收件匣、預測、專案、看板、行事曆、甘特、習慣 | 功能最多、最重;走「萬用任務系統」路線 |
| **TaskNotes** | 一個任務一份筆記 + YAML | 全部用 Bases:清單、看板、行事曆、議程 | 「一個任務一份筆記」跟我們「一份筆記很多卡片」是相反的取捨 |
| **Task Board / Task List Kanban / CardBoard** | 掃描整個 vault 的任務 | 看板 | 跨筆記看板;沒有留言、沒有時間主軸 |
| **Bases**(Obsidian 核心,1.9 起) | 筆記的屬性 | 表格、卡片、清單、地圖 | 核心內建的「表格 / 卡片」—— 但它的一列是一份筆記,不是筆記裡的一行 |
| **Thino** | 每日筆記底下的一條條 memo | 側邊欄時間軸 + 熱度圖 | 「快速記一條 + 日誌感」最像我們的沉浸模式;2.0 起閉源、進階功能收費 |
| Notion / TickTick / Things | 雲端資料庫 | 表格、看板、行事曆、今天 | UI 參考:Things 的「今天」、Notion 的表格內直接編輯 |
| X(Twitter)/ Threads | — | 時間軸 | 手機卡片版面的參考(圓點當大頭照、主題當帳號名稱、FAB) |

### 我們獨有的(要守住)
1. **時間篩選是一等公民**:年月週日連動的一個游標,別人多半是挑日期或查詢語法。
2. **卡片上的署名留言 + 多人同時寫也不會互蓋**(原子寫入、雙胞胎辨識)。其他外掛幾乎都沒有對話。
3. **一份筆記 = 一張看板,欄位跟 Tasks / Dataview 相容**:它們的查詢看得到卡片的日期和循環;Kanban 仍打得開同一份筆記(只是讀不到日期)。
4. **兩種檢視模式**:卡片模式(手機、平板預設)是專屬版面,不是縮小的表格;表格模式(桌機預設,手機也能切換)。
5. **分類 = 顏色 = 狀態**,不必另外學一套欄位。

### 我們的缺口
- 只看得到**一份筆記**;跨筆記(整個 vault)的「今天」目前做不到。
- 拖曳只在排序選「檔案順序」時可以用(拖到別的分類的卡片旁邊就是換分類);其他排序不能拖。
- 沒有提醒 / 通知。
- 按鈕、設定、微調很多,**第一次打開的學習曲線偏高**。
- 顏色有一部分寫死,沒有完全跟著 Obsidian 主題(1.6.1 視覺批次會修)。
- `main.js` 8000+ 行,驗證靠 `tools/` 的測試腳本(要開著 Obsidian),回歸風險隨版本上升。

## 3. 過去更新的檢討

| 觀察 | 建議修正 |
| --- | --- |
| 一版裡常常同時改格式、版面、設定,CLAUDE.md 每版長出一大段「規則」 | 每一版只有**一個主題**;規則收斂成下面的統一原則,版本段落只記「例外」 |
| 版面反覆來回(6px 色帶、狀態標籤、長期…加了又拿掉) | **先 Figma、再程式**:畫面先在「Card Table UI」定案、留言確認,才動 CSS |
| 格式在 1.6.1 大改兩次(@{} 版 → [key:: value] 版) | 1.6.1 發布後格式**凍結**:只加不改;任何格式變動寫一份 ADR(決策紀錄) |
| 設定越來越多(跳轉六個開關、游標、位置…) | 能在介面裡改的就不放設定頁;預設值要好到大多數人不用開設定 |
| 驗證是一次性的 scratchpad 腳本 | 已搬進 `tools/`(`run-tests.ps1`),發版前固定跑 |
| README 一度寫太細、又一度太少 | README:每個大項 2–3 句;細節在 CHANGELOG;設定表跟設定頁同分組 |

## 4. 統一原則(每一版都照這個判斷)

1. **純文字優先**:筆記是唯一的資料;外掛關掉還是一份看得懂的清單。格式只加不改,舊寫法永遠照讀、改到才轉。
2. **時間是主軸**:所有功能都要回答「今天 / 這週 / 這個月要做什麼」。跟時間無關的功能要有很強的理由。
3. **一個寫入者**:所有寫入走 `寫手`,原子讀改寫、一次動最少的行、寧可不寫也不猜。
4. **跟著 Obsidian**:顏色只用 Obsidian 的 CSS 變數、圖示只用 Lucide、快捷鍵用使用者自己的;只做預設主題的深淺兩版。
5. **少色、圖示優先**:顏色只給「分類」「逾期」「週期」「今天」四種意義;其他一律灰階。能用圖示就不用字,字放在提示裡。
6. **卡片模式是一等公民**:手機、平板預設卡片模式,有自己的版面,桌機的東西不能硬塞進去;表格模式在桌機預設,手機也能切換。
7. **介面裡能改的,設定頁就不放**;設定頁照大標分組,新設定放進對應的大標。
8. **每一版都講得清楚**:更新介紹彈窗、版本摘要、CHANGELOG 三處一起寫;README 精簡。
9. **先畫、再做、再量**:Figma 定案 → 實作 → `check4.ps1` 六組全空 + 格式測試全過,才發版。
10. **所見即所得**:編輯和閱讀長得一樣(字、項目符號、待辦的位置不跳);不一樣的地方要寫出原因。1.6.2 起標準是「跟 Obsidian 自己的閱讀 / 編輯一樣」。
11. **點**(2026-09-18 使用者明講,雙關):① 點的位置和時間:常用動作位置固定、點擊次數有上限(像 POS 收銀);② 點對點:卡片之間、卡片和外面的筆記要找得到線索和連結。

## 5. 路線圖(提案)

> 2026-09-18 起,版本怎麼切在 vault 的 Dialogue 文件討論(`0.常用/Card table project/`),這一節只記結果。

### 1.6.x —— 收尾與穩定(現在)
- 1.6.1 已發布:新格式、改到才轉、全部轉換(測試中)、項目符號既往不咎、設定分組、更新介紹。
- **1.6.2 —— 修好使用者回報的問題**(PRD 1.6.2,等使用者簽核):卡片換分類只動這一張、內容照打的存、閱讀模式改用 Obsidian 的 Markdown 渲染、匯出只留長圖、回報問題按鈕、CHANGELOG 只留一份。不改筆記格式。
- 視覺批次:Figma 留言回來後,把寫死的顏色換成 Obsidian 變數、篩選格去色、標題列對齊(使用者在 Dialogue 最後列了 UI/UX 草稿,下一輪討論)。

### 1.7 —— 連結出去(**沉浸模式已取消**,2026-09-18 使用者決定)
> 看板專注在任務;長內容改成「連結到外面的筆記」。
- 卡片 ID(新卡片自動加;先做 EU 和可行性研究,寫 ADR)。
- 抽屜:連結的筆記、參考卡、完整卡片在看板裡的抽屜打開(桌機從右邊、手機從下面),關掉回到原位。
- 移到新筆記、拆出成新卡片;融合保留每一段的日期和主題。
- 分類封存(改名成 `Archive …`);完成和封存在「看」的層面合併(像 Spark),要記完成日期 → ADR。

### 1.8 —— 手機卡片模式
- 方向 C(精簡清單 + 底部抽屜):日期寫在清單上、打開完整卡片有順的動畫、容易按到的「卡片 / 表格」切換鈕。
- 右滑置頂、左滑完成(先實測跟 Obsidian 側欄滑動的衝突)。
- 先用 ux-flow-designer 畫 wireframe,使用者看過才寫程式。

### ~~1.8 —— Kanban 使用者的家~~(不做,2026-09-18 使用者決定)

### 1.9 —— 跨出一份筆記(需要先做決策)
- 選項 A:一個「今天」視圖,唯讀地彙整多份看板筆記。
- 選項 B:提供 Bases 視圖,讓核心的 Bases 讀得到卡片。
- 選項 C:維持一份筆記一張看板,把力氣放在單板體驗。
- 用 tradeoff-analysis-writer 比較後,寫成 ADR 再決定。

### 2.0 —— 長期
- `main.js` 依職責拆檔(仍然不加 build step 的前提下,要先確認 Obsidian 的載入方式)。
- 無障礙(鍵盤走完全部操作、對比)。
- 更多語言。
- 提醒 / 通知(依 Obsidian API 能做到的範圍)。
