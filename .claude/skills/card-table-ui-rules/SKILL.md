# Card Table UI/UX 規則

原則(為什麼)在 `card-table-principles`;這份是**具體怎麼畫**。每一條都是使用者講過的(日期 = 第一次講)。
畫 mockup 或寫版面之前逐條對一次;**畫完自己量**(使用者 09-19:「請自我驗證」),量不到的不要說「對齊了」。

## 1. 對齊

- **三條線 3 / 18 / 22**(09-20 v16 定案,取代舊的 5 / 9 / 18):
  - **3px = 編輯的字**(09-19 v8 Q1「改寫成 3」,以前 5):新增卡片的輸入框、詳細編輯的內容框、搜尋框。編輯欄位**透明、沒有框**,看起來直接打在塊上。
  - **溝 = 3–18**(09-19 v9 Q19,以前 5–13):收合箭頭、分類色條、詳細編輯鈕、塊的圖示。
    溝裡的圖示**放大到 14 填滿整條溝**,置中在 **10.5**。時間篩選那一排也從 3 開始。
  - **18px = 其他所有的字**:卡片上題行的第一個東西(頭像 / 空位 / 主題膠囊)、卡片內容、
    行事曆和設定面板的內容、主題膠囊裡的字(膠囊底色從 15px、內距 2px)。
  - **22px = 標題列上溝後面的第一個圖示**(09-20 v15 Q31,以前 18)= 18 + 標題列的 gap 4。
    四種標題列(時間篩選 / 新增 / 置頂 / 清單 / 未定)都一樣,沒有收合箭頭的表也要畫一個空的溝。
  - `tools/measure.ps1` 的 M2 / M3 / M6 / M7 / M14 在量這幾條。
  - 色條、完成的 ✓ 條不能壓到 18px 的線。
  - **色條和 📌 左緣同一條線 = 3**(09-20 使用者:「色線跟 pin 有沒有對齊?回去看 mockup 的輔助線」)。
    mockup 上畫成 4 / 5 是「溝 5–13」時代留下來的,**以輔助線為準**。
  - **碰到卡片色線不能動**(09-20):滑過整張卡片色條一個 px 都不動;**滑到色條自己**才往下讓 22px、📌 淡淡出現。
    色條算「滑到」的範圍要一路含到卡片頂端(`::before`),不然色條一讓位游標就脫離,會一直閃。
  - 📌 在溝的最上面、色條上方(09-19);釘住的一直在,沒釘的滑過卡片才出現(色條往下讓位)。
- **同一排的東西上下置中**:圓點、▾、圖示、頭像跟旁邊的字同一條中線(09-19 v3:「圓點飄上去了」)。
- **數字對齊**:所有張數(年、日、逾期、週期)跟「9 月」在同一條橫線。
  09-19 v8 留言改了:格子**上排 = 張數、下排 = 字或圖示**(年份、日期、逾期 / 週期的圖示),下排跟週那一格(9/14 – 9/20)同一條線(v9 畫的,等確認)。
- **下拉的 ▾ 不能跟收合箭頭長得一樣**:分類圓點、指派人頭像的 ▾ 縮小(7px)放在右上角。
- 膠囊裡的字上下置中:固定高度 + `display:inline-flex; align-items:center; line-height:1`,中文字在行框裡偏上,需要時補 1–2px(見 CLAUDE.md `標頭補正`)。

## 2. 尺寸

- **不加沒有實質意義的裝飾線**(09-20 使用者:「不隔開,這樣看起來很奇怪而且沒有實質意義,本來就是做極簡」):分組、防誤觸靠**間距**(8–12px),不要畫分隔線。塊之間本來就有的框線、卡片之間的分隔線不算。
- **分類圓點 16px**(09-20 使用者連說兩次「不夠大」;點擊範圍 26 寬),▾ 7px 在右上角。
- **卡片上那一排的尺寸**(09-20 v13–v16 定案):指派人頭像 **17**(跟主題膠囊等高)、**在最前面 18**,
  主題接在後面;沒有指派人留一個 17 寬的空位。卡片上方留 **22px 給 📌**(色條從 22 開始,📌 在 left 4 / top 5)。
  右上角 **✎ 20 × 22 · ⋯ 26 × 22,中間沒有空隙**;所有的 ⋯(標題列、卡片)右緣在同一條線。
- **切換鈕**:整顆切換 26 高(跟標題列一樣)、裡面的鈕 22;標題列上的小圖示鈕 **26 × 22、沒有左右內距**。
- **日期**:區間用**波浪號、不寫星期**(`09-17 ~ 10-18`);單日照舊有星期(`09-19(六)`)。
- **多主題**(09-20 Q35 定案):**只有第一個 `#` 是主題**(分類色膠囊),第二個以後是**副標**:內文色、沒有底色。
- **同一種格子一樣寬**:年 / 月 / 週 / 日四格一樣寬(**v9/v14 起 116px**,最長的「11/23 – 11/29」不用縮字);
  已逾期 / 週期各 52。格子中間是**上下兩排**:上排張數 25 高、下排字或圖示 25 高、`line-height:1`(Q29;箭頭照舊跨整格高)。
- **送出鈕 56 寬**(v9 #2:使用者在鈕上畫了兩條線)—— 左緣對頭像、右緣對標題列的 ⋯。
- **週的標籤永遠一樣寬**:只寫 `M/D–M/D`、兩邊都寫月份;跨年時年份交給年格(寫 `26–27`)。
- **主題膠囊**:圓角 8px、左右內距 2px、高 17px(v6,照使用者在 v3 自己調的 properties;v5 改成圓角 6 被退回)。所有膠囊一起改。主題最多 6 個中文字寬(C22)。
  **而且不准打超過**(09-20 使用者:「要限制使用者不能打超過六個字」):新打的主題(新增卡片、卡片上的主題框、點常用主題帶入)超過 6 個中文字寬就截掉,跳一次提示;
  **舊筆記裡比較長的主題照讀、一個字都不改**(在讀的路徑上截會換掉卡片的身分 `基鍵`),畫面上用 `截寬()` 補「…」,全名放 aria-label。
  ⚠ 使用者在 mockup 上動過 properties 時,**先讀他改的值、猜他想做什麼**,不要只照留言的字面改(09-19:「你有沒有讀我動過的 properties?」)。
- **字距**:數字和括號、連字號之間要留空(「9/19 (六)」「9/14 – 9/20」);年份加字距時用 padding 補回來,保持置中。
- 月、週兩格之間 2px。
- **送出鈕固定高度,不跟著輸入框長高**(1.4.8 就講過,09-19 又講一次)。詳細編輯模式裡,送出鈕自己一排、靠右,不跟內容框同一行。
- **編輯時的主題框不要拉長**(09-20 使用者:「edit 時主題欄位不要拉這麼長,有輸入再長出來」):
  寬度跟著字走(字寬 ≈ ch),空的時候只有一小格,上限 6 個中文字。不要用 flex 撐、不要給 min-width。
- 未完成 / 已完成、封存區這種切換鈕:同一種高度(26px)。

## 3. 字

- **不寫灰色說明字**:placeholder、「點一天當開始」、「按 ↺ 還原…」這類都不要。空的輸入框用淡圖示(house、pen-line)。
  例外(09-19):新增框空白時,pen-line 後面加淡的「…」,讓人知道這裡可以打字(不是字,是記號)。
- 能用圖示就不用字;字放在 title / aria-label。標題列只放圖示(新增卡片不寫「新增卡片」)。
- 頭像就好,不寫名字(頭像 = 名字的第一個字:中文取最後一個字、英文取第一個字母,C17)。
  **頭像統一顏色**(09-20 使用者:「顏色太混亂」):所有指派人同一個淡灰底,使用者不能改;顏色只留給分類、逾期、週期、今天。指派人名單和「使用指派人」開關只在**全域設定**(Obsidian 設定頁),不在看板的面板裡;新增卡片的 ⋯ 留給封存區。
- 圖示已經說清楚的格子不再寫字(逾期、週期只有圖示 + 張數)。
- 張數只寫數字,不寫「張」;月 / 週不寫張數;張數都是灰色,只有逾期(紅)、週期(紫)有顏色。

## 4. 圖示

- 只用 Lucide,**用程式裡已經有的那一個**(`圖備()` 的名字),不要換成新的或畫文字符號:
  逾期 `clock-alert`、週期 `refresh-ccw-dot`、未完成 `circle`、已完成 `circle-check`、封存 `archive`、還原 `archive-restore`、
  新增卡片 `square-pen`、內容空白 `pen-line`、主題空白 `house`、送出 `send-horizontal`、詳細編輯 `maximize-2`、返回 `chevron-left`。
- mockup 也用這些圖示(inline SVG),不用 emoji、不用 ✎ ✓ ☰ 這類字元充數。
  **mockup 不自己拼圖示**:畫之前先查程式那個位置用的是哪個圖示(`圖備(…, [名字])`),照畫(09-19:設定面板拼了「人 + 開關」,使用者問「這是我選的圖案嗎?」)。
- **不能按的東西不畫圖示**(09-19:設定面板標題列的齒輪 —— 使用者會以為可以按)。

## 5. 收起來、彈出來

- 不常用的收進 **⋯**;按 ⋯ **往左**彈出同一排、**樣子跟沒收起來時一樣**(09-19:未完成 / 已完成、封存區、全部)。再按 ⋯ 或點外面收回。
- 「點外面就關」要排除開它的那顆鈕(CLAUDE.md 1.5)。浮動面板掛在 `document.body`。
- 切換成別的內容時(設定、行事曆、封存區)**換掉的是新增卡片那一塊**,時間篩選一直留著。
- **換內容、變大變小一律有動畫**:收合、展開、進出詳細編輯(放大 / 縮小)都用同一種高度滑動(09-19)。
  ⚠ 實作上「詳細編輯」要算成新增那一塊的**一種模式**(新 / 詳 / 設 / 曆),動畫才播得到
  (09-20 使用者:「不是有說詳細編輯要做動畫開合嗎,怎麼也沒做」—— 那時候進出詳細編輯的模式都是「新」,所以是瞬間跳)。
- **動畫只在「真的換了狀態」時播一次**(09-20 使用者:「每點一下都會閃一下」):同一個狀態再點一次不重播,連按也不疊。
- **常用主題那排可以收合**(09-20 使用者):小箭頭放在「☰ 更多主題」**右邊**(展開往右長,不會把那顆擠走);**收起來朝下 ⌄、展開朝右 ›**;**沒有底色也沒有框**(狀態靠方向,不靠框)。新增卡片和詳細編輯兩處都要有,狀態記在這台裝置。
- 單選就是單選:封存區一次只看一區,未完成 / 已完成二選一。
- **草稿的動作要看得到結果**(09-20 使用者:「分類區設定 按封存 會顯示一個預覽 跳到右邊分類封存區」):
  設定面板左半按 🗄(還沒按 ✓)→ 右半多一列**虛線的預覽**並自動選它,底下的卡片清單只剩那一區 ——
  按下去之前看得到「會搬走哪些卡片」。再按一次 🗄 收回。
- 時間篩選標題列只有:⌄ 收合(溝)· 今日(點了回到今天)· ⋯(往左彈出 全部 · 未完成|已完成 · 封存區 · 📅 行事曆)。**不放漏斗、不放行事曆圖示**(使用者 09-19);漏斗在卡片清單的標題列。
- 選到的狀態用底色 + 底線表示就夠,不要再加一顆圖示(封存區拿掉眼睛)。
- 重要的入口不要藏在標題列的小圖示裡(使用者看不出來):詳細編輯鈕要有底色、放在固定位置。
- 滑過會長出東西時(色條 → 「✓ 分類名」),右邊的字跟著被推開(動畫),不要蓋在字上。

## 6. 點

- 點格子中間 = 回到今天 / 選整週;不另外放「今天」「明天」「不排」這種鈕(09-19)。年、月到行事曆視窗裡選。
- 危險動作「再按一次」(✓ + 倒數條),刪除用確認框。
- 常用動作的位置固定(原則 11),不因內容長短移動。

## 7. 顏色

- 只用 Obsidian 的 CSS 變數;mockup 用預設主題深色的值。
- 格子不上色(選到的那格亮一點);顏色只給分類、逾期、週期、今天。「今日」的字色 = 卡片上今天日期的顏色。

## 7b. 使用者 09-20 同意的新規則(UI/UX critic 提的 R1–R6)

- **R1** 卡片內容的字(閱讀和編輯)從 **18** 開始,跟主題的字對齊(09-19 Q2 定案)。編輯時主題照樣是分類色膠囊 + 一條底線,不變成灰色輸入框(Q3)。
- **R2** 所見即所得量水平 + 垂直,每一種行(段落、清單、待辦、段落接清單)都量。
- **R3** 滑過浮出的標籤不換掉、不蓋住原本的字;說明只用 aria-label,不要同時有 title。
- **R4** 主要按鈕(送出)一律 `--interactive-accent`,不跟指派人或分類變色。
- **R5** 淺色主題下,彩色小字(膠囊)對比 ≥ 3:1。
- **R6** 字典的鍵不能寫在註解後面;中英兩份字典的鍵要一樣(`tools/measure.js` 的 M15 會檢查)。
- 有數字的規則都在 `tools/measure.ps1` 量(容許 1px);新規則有數字就加一項。

## 8. mockup 的做法

- 用 claude.ai 的 Design artifact(比 Figma 省 token),每一輪一欄(v1、v2…),舊的留著對照。
- **一版 = 一個 HTML**(09-19):看板、詳細編輯、封存區……全部包在同一張(`V8.dc.html`),不要再拆成 Board / Compose / Archive 三個檔。
- **每出一版就存一份到 vault**:`QA/mockup-<版本>/v<n>/`,從線上版抓(含使用者改過的值),更新 `Mockup <版本> 索引`。
- **畫布只留兩版**(09-20):出新版前,先把畫布上的舊版(含使用者改過的)存進 vault,再從線上畫布拿掉,只留**新的 + 前一版**對照(例:V8 + V9)。
- ⚠ **使用者還在留言時不要動手**(09-20 使用者明講:「我傳給你你不要馬上動工回覆我,我都還沒編輯完成」):
  留言進來**先不讀、不改、不回**,等使用者說「編輯完成 / 可以了 / 做吧」,再一次讀完所有留言、一次改一版。
  Artifact 的即時監看(watch)平常關著,使用者說開工再開;自動回覆不是主對話寫的,看到就在該串更正。
- **留言對答要寫在 mockup 裡**(09-20 使用者明講):每個 Q 旁邊(或同一張的「定案紀錄」區)寫成 **你說 → 我做了什麼 → 狀態**,狀態用徽章:`定案` 綠、`暫定` 黃、`等你回` 灰。這樣看 recap 一眼就知道哪些定了、哪些還開著。vault 的 `留言對答 v<n>.md` 是同一份內容的存檔。
- **存檔要連留言一起存**(09-20 使用者明講):從畫布拿掉一版之前,把那一版的留言對答整理成 `v<n>/留言對答 v<n>.md`(你說什麼 → Claude 怎麼做 → 結論 / 還沒定案的 Q)。畫布上的留言串會留著但變孤兒,vault 這份才是紀錄。
- 發布前先用 Artifact `read`(不帶 path)讀一次整個畫布,不然發布會被擋。
- 有疑慮的地方:畫面上標黃色 `Q<n>`,**問題的字直接寫在 Q 標籤旁邊**(artboard 裡面,同一個位置)。
  **每個 Q 都要在畫面上指得到,能畫的一定畫出來**(現在 vs 提案並排),不要只用字描述(09-19:「哪裡?能在 mockup 表現的你要做出來」)。
  問題用白話:講「哪個東西、現在怎樣、要變怎樣」,不要丟規則代號(R1、18 / 23)讓使用者自己對(09-19:Q2「有夠複雜 看不懂」)。
  ⚠ 不要放到畫布旁邊的便利貼(09-19 使用者:note 太遠要滑來滑去,要 comment)。Claude 沒辦法自己開新的 comment(只能回使用者開的),所以用「寫在旁邊」代替;使用者在 Q 標籤上開 comment 回答。
- 在畫面上畫三條對齊線(5 / 13 / 18px,見第 1 節),自己看得出有沒有對齊。
- 使用者在 mockup 上直接調的 inline style(例如膠囊的內距、圓角)= 新的規格,照他調的值改,然後把值寫進這份。
- 每一版旁邊寫「這一版照哪些留言改了」,一條對一條;不確定的解讀寫出來問。
