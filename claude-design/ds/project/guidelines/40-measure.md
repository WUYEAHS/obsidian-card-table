# 先畫、再做、再量

版面先在 mockup 上定案,實作完**自己量**。量不到的不要說「對齊了」。

## 三支工具(在 repo 裡)

| 工具 | 抓什麼 |
| --- | --- |
| `tools/check4.ps1` | 元素裝不下自己的內容、文字被切掉、跑出板子的左右邊界。每一份報告都要是空的。 |
| `tools/measure.ps1` | 對不齊。照這份系統的數字逐項量,容許 1px。 |
| `tools/probe.ps1` | 畫面上現在發生什麼事(狀態 / 標題列 / 卡片 / 編修框 / 是哪個元素裝不下)。 |

**順序固定:`run-tests.ps1 -FromRepo` → `measure.ps1` → `check4.ps1`,中間不要插別的事。**
`run-tests` 會重載外掛 = 乾淨狀態;自己手動操作過看板(開過設定模式、封存區、編修框)之後再量,
量到的是上一次留下來的畫面,會報出一堆假的失敗。被污染了就再跑一次,或 `probe.ps1 reset`。

## check4 量幾組

平常疊代跑快速版(中 / 英 × 桌機 1280 兩組)。**發版前**或大改版面告一段落才跑 `-Full`:
中文 / 英文 × 桌機 1280 / 看板 800 / 手機看板 390 / 手機看板 360,八種組合。

這是唯一抓得到「英文被切掉」「手機溢出」的方法 —— **靠眼睛看一定會漏**。
改任何寬度、字級、flex 之後都跑一次。

⚠ 手機那兩組量的是**看板寬**,不是視窗寬。桌機 Obsidian 視窗再窄都還留著左側 ribbon 和分頁邊框,
420px 的視窗只剩 306px 給看板,比任何一支真的手機都窄,會報出一堆手機上根本不存在的切字。

## 兩個會騙人的地方

- **量速度、跑測試時 Obsidian 視窗要露出來。** 縮小或被蓋住時 Chromium 把計時器拖到快 1 秒。
- **手機的版面問題桌機模擬不出來**(模擬是 is-tablet)。請使用者在手機上跑「匯出版面診斷」,
  會寫一份每個編輯器由外到內的尺寸、樣式和命中規則的筆記。

## 死掉的 CSS 規則

最難發現的 bug:**CSS 寫了規則,但 class 根本沒掛上去**。
`tk-釘列`、`tk-循排`、`tk-補排` 都發生過 —— styles.css 有整段規則,程式卻沒 `addClass`,
於是那段是死的,直到某天補上 class,版面突然變了。

加新的版位規則時,**順手確認元素真的有那個 class**;拿掉元素時,順手把它的規則一起拿掉。
